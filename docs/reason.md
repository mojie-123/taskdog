# 坐标系理解错误总结

## 错误背景

在分析 Piper 机械臂抓取香蕉的 IK 问题时，长期误判「j5>0 是水平抓取，j5<0 是从上往下抓取」，实际上完全反了。

---

## 错误1：混淆了 gripper_base 的「approach 轴」和「fingertip 轴」

### 错误做法
将 `gripper_base X 轴`（GraspNet 的 approach 方向）当成了「夹爪指尖方向」来判断抓取姿态。

### 正确理解

| gripper_base 轴 | GraspNet 含义 | 物理解释 |
|----------------|--------------|----------|
| **X 轴** | approach 方向 | 夹爪**接近**物体的方向（运动轨迹方向），不是指尖朝向 |
| **Y 轴** | closing 方向 | 手指张开/闭合的方向（夹持轴） |
| **Z 轴** | fingertip 方向 | **指尖真正朝向的方向** |

### 判断「从上往下抓」的正确标准
- **approach 朝下（X 轴 Z 分量大负值）**：仅说明夹爪从上方运动过来，不代表指尖朝下
- **fingertip 朝下（Z 轴 Z 分量大负值）**：才是真正的「指尖向下插入」
- **两者同时满足**：才是真正的「从上往下竖直抓取」

### 具体数据对比（ARM_INIT vs IK解）

```
ARM_INIT (j5=+1.2):
  approach (X) in world: [-0.898,  0.012, -0.440]  approach有-Z分量
  fingertip (Z) in world: [+0.440,  0.002, -0.898]  指尖主要朝-Z（向下）✓ 从上往下抓

IK解 (j5=-1.057):
  approach (X) in world: [-0.293, -0.121, -0.948]  approach有-Z分量（看似向下）
  fingertip (Z) in world: [+0.926, +0.211, -0.313]  指尖主要朝+X（水平朝香蕉）← 水平侧向抓
```

**教训：仅看 approach 的 Z 分量就下结论「竖直向下抓」是错的，必须同时看 fingertip（Z 轴）方向。**

## 错误2：没有将 arm_base_link 的坐标轴换算到世界坐标系

### 错误做法
直接在 arm_base_link 坐标系里看向量分量，用「Y 分量大正值 = 朝前方」等直觉判断。

### 正确理解

arm_base_link 与 base_link 的旋转关系：`rpy=0,0,0`（无旋转），但 base_link 本身在世界里转了约 90°（quat w≈0.71，绕 Z 轴约 90°），导致：

```
arm_base +X in world: [ 0.010,  1.000,  0.007]  ← 世界 +Y 方向（非直觉的「前方」）
arm_base +Y in world: [-1.000,  0.010,  0.002]  ← 世界 -X 方向
arm_base +Z in world: [ 0.002, -0.007,  1.000]  ← 世界 +Z 方向（向上）
```

**教训：在 arm_base_link 坐标系里「+Y 分量大」不等于「朝机器人前方」，必须先算 robot quat 对应的旋转矩阵，再将向量换算到世界坐标系，才能用世界方向（+X=香蕉方向，+Z=向上）判断。**

## 错误3：孤立看 j5 值，不追踪完整运动学链

### 错误做法
想当然地认为「j5 正值 = 腕部某方向弯曲」，没有考虑 j1~j4 的累积旋转效果。

### 正确理解

joint5 的 `origin rpy="-1.5708 0 0"` 将其旋转轴在 arm_base 里变为约 **-Y 方向**（由 j1~j4 的累积变换决定）。在 j2=+1.5、j3=-1.5 的基础上：

- **j5 增大（正方向）**：link5/fingertip 从「朝下」向「朝 arm_base -Y（世界+X）」旋转，即朝香蕉水平伸出方向翻转→ 指尖从下方转向水平
- **j5 减小（负方向）**：link5/fingertip 继续从「朝下」向另一方向翻转
- **j5=0 时**：fingertip 几乎纯朝世界 -Z（向下）
- **j5=+1.2（ARM_INIT）**：fingertip 主要朝世界 -Z 偏向世界 +X，仍然是从上方朝香蕉 ✓
- **j5=-1.057（IK解）**：fingertip 主要朝世界 +X（水平朝香蕉），是水平侧向抓取

**教训：j5 的旋转效果必须从 FK 数值验证，不能脱离上游关节（j1~j4）的累积旋转状态凭直觉判断正负含义。**

## 错误4：「IK 没有找到某种解」≠「该解不存在」

### 错误做法
对每个 roll 角用 j5pos seed 都没找到 j5>0 的有效解，就直接结论「j5>0 的从上往下解在几何上不存在」。

### 正确理解
IK 数值求解器是局部优化，找不到某解只说明从该 seed 出发的梯度路径没有到达那个局部极小值，**不代表解不存在**。特别是当旋转约束很强、seed 距目标解较远时，求解器可能跳到另一个分支。

**教训：IK 找不到解时，要分离「解不存在」和「seed 不对导致未找到」两种情况，通过改 seed 或分析运动学结构来区分。**

## 正确的抓取姿态判断流程

1. 用 FK 算出目标关节角下 `fk_gripper(q)` 的完整 4x4 变换矩阵
2. 取 `T_gb[:3, 2]`（Z 轴 = fingertip 方向）
3. 乘以 `R_base2world`（从 robot quat 算出）换算到世界坐标
4. 看世界坐标 Z 分量：大负值（≈-1）= 指尖向下 = 从上往下抓；接近 0 = 水平侧向抓
5. **同时检查 X 轴（approach）和 Z 轴（fingertip），两者共同决定抓取姿态**

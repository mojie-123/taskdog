## 一、PIPER_COLLIDERS 字典是怎么确定的？

### 信息来源：原始 URDF + 肉眼/工具量取

原始 URDF（`SOURCE_M20_Piper.urdf`）里，Piper 臂的每个 link 的碰撞体都是 **STL mesh**，例如：

```xml
<link name="link2">
  <collision>
    <geometry>
      <mesh filename="./meshes/link2.STL" />  <!-- STL 文件，几千个三角面 -->
    </geometry>
  </collision>
</link>
```

这些 STL 碰撞体对 PhysX 来说太复杂（运行慢、内存大），所以需要手工用 primitive（box/cylinder）来近似替代。

**字典的值是怎么来的？** 有两种方法结合使用：

### 方法 1：从 URDF 的惯性参数/质心位置推算

每个 link 的 `<inertial>` 标签里有质心位置（`origin xyz`），可以推断出 link 的大致几何中心和尺寸。例如 link2 的质心：
```xml
<origin xyz="0.198666 -0.010926 0.001421"/>
```
质心 x ≈ 0.20m，说明 link2 沿 X 方向延伸约 0.40m（对称的话质心在中间），和字典里 `"box", "0.14 0 0", size "0.28 0.07 0.07"` 吻合（28cm 长，质心偏移 14cm）。

### 方法 2：在 Isaac Sim / usdview 里打开 STL 目测量取

可以直接在 Isaac Sim 的 Stage 面板里打开已转换的 USD，看每个 link 的实际 mesh 包围盒（Bounding Box），然后用合适的 primitive 形状去近似：
- 长条形关节（link2、link3）→ box
- 圆柱形旋转关节（link1、link4、link6）→ cylinder
- 夹爪基座（gripper_base）→ box

### 方法 3：参考 URDF 里已有的 primitive 碰撞（M20 底盘部分）

原始 URDF 里，M20 底盘的 link（`base_link`、腿部各关节）已经使用 box/cylinder 作为碰撞体了，可以直接参考它们的尺寸写法，确认坐标系方向和原点偏移的规律。

### link7/link8 为什么不加进字典？

因为夹爪手指的形状细长且不规则，box/cylinder 近似误差太大，会导致抓取时手指碰撞范围不准——手指「穿进」物体或「提前触碰」。所以保留 STL mesh 作为碰撞体，再通过 patch 脚本手动补写进 USD。

## 二、config.yaml 是我们写的还是自动生成的？

**是脚本运行时自动生成的，不是手工写的。**

注意两个文件的末尾注释：

```yaml
# m20_piper_single/config.yaml
## Generated by UrdfConverter on 2026-09-03 at 12:12:55.

# assets/config.yaml（旧版）
## Generated by UrdfConverter on 2026-08-07 at 11:22:28.
```

Isaac Lab 的 `UrdfConverter` 每次运行后，会在输出目录下自动写一个 `config.yaml`，记录本次转换用的所有参数（`asset_path`、`usd_dir`、`make_instanceable` 等）。这是 Isaac Lab 的内置行为，目的是：
- **复现记录**：下次想用同样参数重新转换时，可以直接看这个文件
- **调试参考**：出问题时可以查看当时的转换参数

内容完全来自 `convert_m20_piper_urdf.py` 里 `UrdfConverterCfg(...)` 的参数，例如：
```python
cfg = UrdfConverterCfg(
    asset_path=str(urdf_path),          # → asset_path: .../M20_Piper_lightweight.urdf
    usd_dir=str(OUTPUT_DIR),            # → usd_dir: .../m20_piper_single
    usd_file_name="M20_Piper.usd",      # → usd_file_name: M20_Piper.usd
    make_instanceable=True,             # → make_instanceable: true
    collider_type="convex_hull",        # → collider_type: convex_hull
    ...                                 # 其余参数一一对应
)
```

我们不需要手动维护这个文件，也不应该手工修改它（修改了也不影响任何行为，它只是记录，不是输入）。

## 三、STL 文件是什么、包含什么内容？

### STL = Stereolithography（立体光刻格式）

STL 是一种极其简单的 **3D 网格文件格式**，由机械 CAD 软件（SolidWorks、Fusion 360 等）导出。正如文件注释所示：

```xml
<!-- This URDF was automatically created by SolidWorks to URDF Exporter -->
```

M20_Piper 的 STL 文件就是 SolidWorks 把机器人各零件的 3D 模型导出的结果。

### STL 的内容

STL 只包含一件事：**三角面片列表**。每个三角面片由三个顶点坐标和一个法向量组成：

```
三角面 1:
  法向量: (nx, ny, nz)
  顶点1:  (x1, y1, z1)
  顶点2:  (x2, y2, z2)
  顶点3:  (x3, y3, z3)

三角面 2:
  ...
```

STL **没有**：颜色、材质、UV 贴图、骨骼、动画——只有几何形状。

### 两种编码

| | ASCII STL | Binary STL（本项目）|
|---|---|---|
| 可读性 | 人类可读文本 | 不可读二进制 |
| 文件大小 | 大 | 小（约 1/10）|
| 识别方式 | 以 `solid` 开头 | 以 84 字节头开始 |
| 本项目 | 无 | 全部是 Binary STL（文件名含 `STL_BINARY_`）|

USD 里的 `/visuals/link7/link7/node_STL_BINARY_/mesh` 这个 prim 名称中的 `STL_BINARY` 就是 UrdfConverter 在转换时把 Binary STL 的内容展开成 USD Mesh 属性后留下的命名痕迹。

### STL 在本项目的作用链

```
机械设计师在 SolidWorks 建模
    │
    ▼ 导出
link7.STL（二进制，包含夹爪手指的几千个三角面）
    │ 被 URDF 引用
    ▼
SOURCE_M20_Piper.urdf
  <collision><mesh filename="./meshes/link7.STL"/>
    │ UrdfConverter 尝试转换，但 mesh collision 支持不完整
    ▼
base.usd 里 /visuals/link7/.../mesh  ← STL 顶点数据在这里（6258个点）
            /colliders/link7/link7   ← 空 Xform（转换失败，什么都没有）
    │ patch 脚本把 visuals 的数据复制到 colliders
    ▼
/colliders/link7/link7  ← 现在有了 6258 个顶点，类型是 Mesh
    │ PhysX 加载时做 convexDecomposition
    ▼
仿真中手指有了真实碰撞体，能抓住香蕉
```

### 为什么 link7/link8 的顶点是 6258 个？

这是 SolidWorks 导出时自动决定的三角面密度。夹爪手指形状细长弯曲，需要较多三角面才能准确表示。6258 个顶点对应约 2000 多个三角面（每个三角面3个顶点，但顶点共享，所以不完全是整除关系）。对比之下，build 脚本里 link2 替换成的 box 只有 8 个顶点——简单 primitive 的计算成本是 STL mesh 的几百分之一。

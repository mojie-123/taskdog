# 一、URDF / USD / USDA 三种格式讲解

## 1. URDF（Unified Robot Description Format）

**本质**：一种 XML 格式的机器人描述语言，源自 ROS（Robot Operating System）生态。

**描述内容**：
- `<link>`：每个刚体部件，包含惯性参数（质量、惯性矩）、视觉几何（mesh/box/cylinder）、碰撞几何
- `<joint>`：连接两个 link 的关节，定义类型（fixed/revolute/prismatic）、轴、限位、阻尼
- 关节树：所有 joint 构成一棵以根节点（base_link）为根的有向树

**局限性**：
- 只能描述树形结构，不支持闭链
- 只有 XML 标量数据，不含 GPU 加速渲染资源
- Isaac Sim 的 UrdfConverter 对某些几何类型支持不完整（如 `<collision><mesh>` 会被忽略，即本项目 link7/link8 的问题）

**本项目中的 URDF 文件**（见后文详述）：
- `deps/deep_robotics_model/M20_Piper/urdf/M20_Piper.urdf`（外部依赖，原始源文件）
- `m20_piper_single/SOURCE_M20_Piper.urdf`（脚本拷贝的备份）
- `m20_piper_single/M20_Piper_lightweight.urdf`（脚本生成的轻量化版本）

---

## 2. USD（Universal Scene Description）

**本质**：Pixar 开发的通用场景描述标准，现由 NVIDIA 主导推进用于仿真/渲染领域（Isaac Sim 的核心格式）。

**两种编码**：
- **USDC**（`.usd` 后缀时通常是这种）：**二进制压缩格式**，文件小，加载快，不可直接阅读。`PXR-USDC` 是其文件头 magic bytes。
- **USDA**（`.usda` 后缀）：**人类可读的 ASCII 文本格式**，类似 JSON/Python，便于手动编写和版本控制。`.usd` 后缀也可以存储 USDA，但本项目中 `.usd` 基本都是 USDC 二进制。

**核心概念**：
- **Prim（Primitive）**：USD 场景的基本节点，等价于场景树中的一个对象（Mesh、Xform、Camera 等）
- **Attribute**：Prim 上的属性（`points`、`physics:mass` 等）
- **API Schema**：给 Prim 附加的功能标签（`PhysicsRigidBodyAPI`、`PhysicsCollisionAPI` 等），类似 Python 的 mixin
- **Reference / SubLayer / Payload**：USD 的核心合成机制——一个 USD 文件可以引用（reference）另一个文件，被引用文件的内容被「叠加」进来。这实现了模块化：
  - **SubLayer**：整个 layer 叠加，强度最弱
  - **Reference**：把另一个文件的某个 prim 挂载到当前 prim 下，最常用
  - **Payload**：延迟加载的 Reference，大文件按需加载
- **Stage**：USD 的「场景」，由多个 Layer 通过合成规则叠加得到最终可见的状态
- **Instanceable**：USD 的实例化机制，几何数据只存一份（Prototype），多个实例共享它（Instance Proxy）。这正是 `make_instanceable=True` 的作用，也是为什么不能直接用 `stage.GetPrimAtPath()` 修改 link7/link8 碰撞体的原因。

**和 URDF 的关系**：URDF 是 USD 的「输入源」，通过 Isaac Sim 的 `UrdfConverter` 工具自动转换为 USD。转换之后 URDF 就不再被仿真直接使用，USD 才是 Isaac Sim 加载的格式。

---

## 3. USDA vs USDC

| 特性 | USDA | USDC（`.usd` 二进制） |
|---|---|---|
| 可读性 | 人类可读 ASCII | 不可读，需 pxr 工具 |
| 文件大小 | 大（明文存储） | 小（压缩存储） |
| 加载速度 | 慢 | 快 |
| 适合场景 | 手工编写、调试 | 生产/仿真运行 |
| 本项目用法 | 手工作者的机器人定义、Isaac Sim GUI 场景文件 | URDF 转换输出、外部 piper 臂的 USD |

### 各文件作用详解

**`M20_Piper_lightweight.urdf`**
- `build_m20_piper_urdf.py` 的输出，是 URDF 转 USD 的实际输入
- 「轻量化」指：Piper 臂的 mesh 碰撞体已替换为 box/cylinder primitive（减小转换后 USD 体积，提升 PhysX 碰撞性能），link7/link8 保留 STL mesh
- mesh 路径已从相对路径改为绝对路径

**`SOURCE_M20_Piper.urdf`**
- 对原始厂商 URDF 的原样备份（`shutil.copy2`），**没有任何修改**
- 纯参考用，不会被任何脚本直接加载

**`M20_Piper.usd`（入口 USD）**
- USDC 二进制，体积极小（~1.5KB），本身不含任何几何数据
- 作用：把 `configuration/` 下的 4 个子文件通过 **SubLayer 或 Reference** 组合成完整机器人描述
- 这是 `m20_piper_single.py` 里 `M20_PIPER_SINGLE_USD` 指向的文件，Isaac Sim 加载这个作为机器人 prim 的起点

**`configuration/M20_Piper_base.usd`（~30MB，最大的文件）**
- 存储所有 link 的 **视觉网格**（visuals/linkN 下的 Mesh prim，包含 STL 的所有顶点/法线数据）和 **碰撞网格**（colliders/linkN 下）
- 因为包含完整 STL 数据，所以体积最大
- 被 patch 脚本修改：link7/link8 的碰撞 prim 从空 Xform 改为含真实顶点的 Mesh

**`configuration/M20_Piper_physics.usd`**
- 存储所有物理属性的 **声明**（Spec）：
  - 每个 link 的 `PhysicsRigidBodyAPI`、质量、惯性
  - 每个 joint 的 `PhysicsRevoluteJoint`、限位、阻尼
  - 每个碰撞体的 `PhysicsCollisionAPI`
- 被 patch 脚本修改：link7/link8 的碰撞 prim 添加了 `PhysicsCollisionAPI` 和 `physics:approximation=convexDecomposition`

**`configuration/M20_Piper_robot.usd`**
- 存储机器人 Articulation 的关节约束和驱动参数（PhysicsArticulationRootAPI、关节 drive）
- 体积小（~2KB）

**`configuration/M20_Piper_sensor.usd`**
- 存储传感器定义（相机、激光雷达等）
- 体积极小（~650B）

## 四、关键要点总结

1. **当前仿真实际用的文件**：`m20_piper_single/M20_Piper.usd`（及其 configuration 子目录），由 `m20_piper_single.py` 的 `ArticulationCfg` 引用。

2. **每次修改机器人结构都需要重新走完三步流程**：build → convert → patch。其中 convert 需要启动 Isaac Sim，patch 不需要。

3. **USD 的分层结构**（base/physics/robot/sensor）是 Isaac Sim UrdfConverter 的标准输出模式，职责分离，便于单独修改某一层（如 patch 只需要改 base 和 physics，不碰 robot 层）。

4. **USDC 二进制不可直接阅读**，`piper/` 和 `m20_piper_single/configuration/` 下的 `.usd` 文件都是 USDC，需要通过 pxr Python API 或 USD 工具（`usdview`、`usdcat`）读写。

5. **assets/configuration/（旧版）和 m20_piper_single/configuration/（新版）**：旧版是 8 月 7 日的历史遗留，新版是 9 月 3 日重新生成并 patch 的，当前仿真使用新版。
